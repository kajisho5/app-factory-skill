あなたはAppleプラットフォーム（iOS / iPadOS / macOS）のアプリ開発のエキスパートです。以下の仕様で、新規アプリ「宛名印刷 はがき・封筒」をゼロから開発してください。

## 背景とコンセプト

年賀状や挨拶状の宛名印刷アプリは需要が大きい一方、既存アプリは広告が多く、印刷直前に課金画面を挟むものが目立ちます（対象競合は評価3.59、評価数844件。低評価レビューの言及数は広告10・課金2が中心）。本アプリはその不満を潰しにいきます。

- 広告なし（広告SDKを一切入れない）
- サブスクなし（あるのは買い切りの一回払いだけ）。印刷の直前など、作業の佳境で課金画面を出さない
- 住所録CSVの取り込みに対応し、年賀状シーズンに大量の宛先を一括登録できる
- 住所データは端末内のみに保存し、外部サーバーに送らない

判断に迷ったら、この原則に反しない方を選んでください。

## 技術条件

- SwiftUI + Swift（最新の安定版）、iOS 26.0以上、iPhone / iPad対応。Macは「Designed for iPad」で動作する前提（Mac専用UIは作らない）
- サードパーティライブラリ禁止（Apple純正フレームワークのみ）
- データ保存は SwiftData、連絡先の取り込みは Contacts、印刷は AirPrint（UIPrintInteractionController）、PDF出力は UIGraphicsPDFRenderer、縦書きの描画は Core Text
- 課金は StoreKit 2、非消耗型のアプリ内課金1点のみ
- Xcodeでそのまま開いてビルドできる形で納品すること（XcodeGenの project.yml 方式でも可。その場合は生成手順をREADMEに明記）
- UIは日本語。コード内の識別子とコメントは英語

## 機能仕様

### 1. 宛先リスト
- 宛先の登録・編集・削除: 氏名、連名（配偶者など）、敬称（様/先生/御中などのプリセット＋自由入力）、郵便番号、住所、メモ（喪中・転居先など）
- iPhoneの連絡先から取り込み。連絡先へのアクセスが「一部の連絡先のみ」に制限されている場合は、許可された連絡先だけを対象にし、許可範囲を広げる方法を案内する
- **CSV取り込み**: 氏名/連名/郵便番号/住所/メモ の列を持つCSVを読み込む
  - 文字コードは UTF-8（BOMあり・なしの両方）と Shift_JIS に対応する。Excelで作ったCSVを想定し、Windowsの機種依存文字（①、髙 など）を含むファイルでも文字化けしないことをテストする
  - 取り込み前に列のマッピング確認画面を出す
  - 列不足などで取り込めない行はスキップし、取り込み後に「取り込んだ件数／スキップした件数と理由（行番号つき）」をユーザーに知らせる
  - テンプレートCSVを共有シートで書き出せること
- グループ分け（例: 年賀状2027、仕事関係）と、グループ単位の一括印刷
- 印刷済みフラグと印刷日時の記録（出し忘れ・二重印刷の防止）

### 2. レイアウト
- 用紙: はがき（100×148mm、年賀はがき含む）、封筒 長形3号・長形4号・洋形2号・角形2号
- 縦書き・横書きの両対応
- 縦書き時は、住所の算用数字を1文字ずつ漢数字に置き換えるオプションを用意する（例: 1-13-3 → 一-一三-三）。「一丁目十三番三号」のような表記への変換は不要。ハイフンは縦書き用の縦棒の向きで描画する
- 郵便番号は各用紙の郵便番号枠の位置に自動配置する。枠の座標（mm）は用紙ごとに定数ファイルに切り出し、根拠（日本郵便の規格資料など）をコメントで示す。入力された郵便番号はハイフンを除いた7桁の数字として検証し、形式が異なる場合は印刷前に警告する
- 差出人（自分の住所・氏名）を登録し、宛名面への印刷ON/OFFを切り替え
- フォントは明朝・ゴシックなど数種類から選択（旧字体・異体字の人名が欠けないフォントを選ぶ）。文字サイズは住所の長さに応じて自動調整し、はみ出す場合は警告表示
- 印刷位置の微調整（上下左右をmm単位でオフセット調整し、プリンターごとの設定として保存）

### 3. プレビューと印刷
- 実寸に近い印刷プレビュー（用紙の枠と郵便番号枠を表示）
- 1件印刷と、グループの一括連続印刷
- PDFとして書き出して共有・保存も可能

### 4. 設定・その他
- 差出人プロフィールは複数登録可（自宅用・仕事用）
- レビュー依頼は、印刷成功が5回を超えた後の自然なタイミングで1回だけ
- プライバシーポリシーと利用規約のリンク欄（URLは定数ファイルに切り出す）

### 5. 工数が逼迫した場合
- 年賀状シーズン（11〜12月）に間に合わせるため、コアの印刷フロー（宛先リストとCSV取り込み → レイアウトとプレビュー → 印刷とPDF）を最優先する
- 封筒の種類 → 差出人プロフィールの複数登録 → 縦書き時の漢数字置換オプション の順に後回しにしてよい
- 宛先の取り込み・レイアウト・プレビュー・印刷のコアフローは削らない

## 課金設計

- 無料版でできること： 宛先登録10件まで、連絡先からの取り込み（10件の範囲内）。印刷機能そのものは無制限（透かし等は入れない）
- 「Pro（買い切り）」¥800 の非消耗型IAP 1点（StoreKit商品ID: `atena-print.pro`）で解放するもの： 宛先無制限＋CSV取り込み＋PDF出力
- 無料版の制限は、ユーザーがぶつかる前に画面上で明示する。宛先の一覧と登録画面に上限と現在の件数（例: 7/10件）を常時表示し、11件目を登録しようとして初めて制限に気づく形にしない。連絡先から取り込むときも、選択画面で残り件数を表示し、上限を超える分は取り込まない旨を取り込み前に示す。CSV取り込みとPDF出力がPro機能であることは、ボタンの時点で分かる表示にする
- 課金画面に「これは買い切りです。毎月・毎週の支払いは発生しません」「広告は今後も入れません」と明記し、購入ボタンには価格をそのまま表示する
- iPhone / iPad / Mac はユニバーサル購入とし、1回の購入で全プラットフォームで使えるようにする
- 購入の復元（リストア）ボタンを課金画面と設定画面の両方に置く
- 無料お試し・期間限定価格など誤認させる表現、隠れたサブスク、印刷直前・PDF書き出し直前に課金画面を挟む導線は使わない

## 権限とプライバシー

- 連絡先（NSContactsUsageDescription）: 「宛名印刷のために連絡先へアクセスします。連絡先の内容が外部に送信されることはありません」
- トラッキングなし（ATTダイアログを出さない）、解析SDKなし
- App Privacy（プライバシーラベル）が「データを収集しない」になる設計にすること
- プライバシーラベル等の申告内容と実装を一致させる。申告と異なるデータ収集が必要になった場合は、勝手に実装せず報告する

## 共通デフォルト（全アプリ共通）

### デザイン原則
- **Appleの Human Interface Guidelines (HIG) に必ず沿うこと。** ナビゲーション構造、タップ領域（iPhone / iPad は44×44pt以上）、Safe Area、Dynamic Type、ダークモード、SF Symbolsの使い方など、HIGの規定から外れるUIを勝手に作らない。HIGと自分の判断が衝突したらHIGを優先し、その旨を報告する [1]
- iOS標準の見た目と操作感を基本とし、独自UIは必要最小限にする
- **レイアウト**: サイズクラス（実際に使える幅と高さ）でレイアウトを決め、端末の種類や向きで決め打ちしない [2]
- **画面の向き**: iPhoneは縦向き（ポートレート）固定。向きを固定していても、ウィンドウサイズの変化（Mac上のiPhoneミラーリング、iOS 27以降のシーンのリサイズ）でレイアウトが崩れないようにする。iPadは全方向に対応し、ウィンドウ表示で自由にリサイズされても崩れず、最小ウィンドウでも主要機能が使えるようにする。印刷プレビューは、広い幅（iPadの横向きなど）で用紙全体が見えるレイアウトにする。`UIRequiresFullScreen` は使わない [2][3]
- **iPhoneの操作性**: 片手操作を想定し、主要アクションは画面の下部〜中部に配置する。シート（ハーフモーダル）の開閉操作は全画面で一貫させる
- **iPadのレイアウト**: 画面幅を活かしたレイアウトにする（宛先リスト＋プレビューの2ペインなど。iPhone画面の引き伸ばしにしない）。ポインタのホバー効果と、ハードウェアキーボードの主要ショートカット（新規宛先、検索、印刷）に対応し、主要コマンドはiPadのメニューバーにも出す（メニューバーにしかない機能は作らない）
- **キーボード表示時**: 住所入力などのフォーム入力時、ソフトウェアキーボードで入力中の項目や確定ボタンが隠れないよう、スクロールやレイアウト回避を行う
- **起動画面**: Launch ScreenをInfo.plistで構成する（iOS 27 SDK以降は提出の必須条件）。シンプルにし、広告・ロゴアニメ・待機演出を入れない。起動したらすぐ操作できる状態にする [4]

### Mac
- Macでの提供形態： Designed for iPad
- Mac専用UIは作らない。iPad版のレイアウトがMacのウィンドウサイズで崩れないこと、Macから AirPrint で印刷できることを確認する

### アプリアイコン
- レイヤードアイコン（.icon）を **Icon Composer**（Xcode同梱のApple公式ツール）または **fresnel**（kajisho5/fresnel）で作成し、iOSの **Liquid Glass** スタイルにする [5][6][7]
- キャンバスは1024×1024px。レイヤーは角丸マスクを付けない正方形で渡し、前景はベクター（SVG / PDF）を優先する
- ハイライト・影・ぼかしなどの効果は描き込まず、システムの効果に任せる
- デフォルト／ダーク／クリア（ライト・ダーク）／ティント（ライト・ダーク）の外観をすべて用意し、それぞれで見え方を確認する
- アイコンに文字を入れない。小さいサイズでも判別できるシンプルなグリフにする [5]

### 品質・標準対応
- **ダークモード**: 色はアセットカタログまたはシステムカラーで定義し、ライト／ダーク両モードで表示を確認する（印刷プレビューの用紙はダークモードでも白い紙として表示する）
- **Dynamic Type**: システムの文字サイズ変更に対応し、最大サイズ（アクセシビリティサイズを含む）でもレイアウトが崩れない
- **アクセシビリティ**: 主要な操作要素にVoiceOverラベルを付け、読み上げ順序を画面の論理順に合わせる。テキストと背景のコントラスト比を両モードで確保する（17pt以下は4.5:1以上、18pt以上と太字は3:1以上）。隣接するコントロールの間に十分な余白をとる（目安： ベゼルありは周囲約12pt、ベゼルなしは約24pt）。カスタム書体でも最小サイズ（iPhone / iPad 11pt、Mac 10pt、Watch 12pt）を下回らない。色だけで情報を区別しない（印刷済み・未印刷はアイコンや文字でも示す）。「視差効果を減らす」がオンなら自動・反復アニメーションを抑え、「透明度を下げる」「コントラストを上げる」がオンでも文字が読めるようにする [8]
- **ローカライズ前提**: UI文字列はハードコードせず String Catalogs（.xcstrings）で管理する（初期言語は日本語）
- **権限拒否・空状態**: 連絡先の権限が拒否された場合の代替導線（設定アプリへの誘導と、手入力・CSV取り込みへの案内）と、宛先が空の状態の画面を必ず用意する
- **プライバシーマニフェスト**: PrivacyInfo.xcprivacy を用意し、必須理由APIの申告を済ませる [9]
- **データ保持**: 住所データはアプリのコンテナに保存してiCloudバックアップ対象とし、アップデートや機種変更でデータが消えない設計にする

### デモモックと成果物の形式
- 納品時、デモ用の画面モックを用意する: **iPhone / iPad / Mac / iPhone Duo（iPhone 2台並び）**（MacはDesigned for iPadの画面で可。Watch版はないためWatchのモックは不要）
- モックは主要画面を実機フレームで表示した、App Store掲載素材にも転用できる品質のものにする。スクリーンショットとして使う画像は App Store Connect の必須サイズで書き出す（透過なし。サイズは提出時に最新の仕様を確認）[10]
- **iPhone Duo（2台並び）モック**: 2画面の状態（時刻・データ内容・選択状態・ライト／ダーク）を一致させ、宛先一覧と印刷プレビューのように役割分担が分かる並びにする。端末のサイズ・角度・余白を揃える。小さく表示しても文字が読めるようにする
- **モック・スクリーンショット・サンプルCSVには、明らかに架空の氏名・住所・郵便番号を使う**（実在の人物・住所を使わない。宛名アプリなので特に厳守）
- 確認はiPhoneで行うため、**アイコンやモックなどの視覚成果物は、SVG原版に加えてPNGのプレビューを必ず添えること**（SVGだけでは見られない）
- アイコンとモックの成果物はリポジトリ内の `deliverables/` フォルダにまとめ、READMEに一覧を載せる
