あなたはAppleプラットフォーム（iOS / iPadOS）のアプリ開発のエキスパートです。以下の仕様で、新規アプリ「誠実QRリーダー」をゼロから開発してください。

## 背景とコンセプト

App StoreのQRリーダー系アプリは、無料に見せて高額な週額サブスクへ誘導するものが多く、対象競合（評価3.13、評価数861件）の低評価レビューは「課金」「詐欺のようだ」という不満に集中しています（低評価レビュー47件中の言及数： 課金27・詐欺感14・更新放置2・UI1）。本アプリはその真逆を行きます。

- 広告なし（広告SDKを一切入れない）
- サブスクなし（定期課金なし。あるのは買い切りの一回払いだけ）
- スキャン結果を外部サーバーに送らない（全処理を端末内で完結）

この「誠実さ」自体が商品価値です。実装の判断に迷ったら、この3原則に反しない方を選んでください。

## 技術条件

- SwiftUI + Swift（最新の安定版）、iOS 26.0以上、iPhone / iPad対応（Mac・Watchは対象外）
- サードパーティライブラリ禁止（Apple純正フレームワークのみ）
- カメラでの読み取りは AVFoundation、写真ライブラリの画像からの読み取りは Vision（バーコード検出）、QR生成は Core Image
- 履歴の保存は SwiftData
- 課金は StoreKit 2、非消耗型のアプリ内課金1点のみ
- Xcodeでそのまま開いてビルドできる形で納品すること（XcodeGenの project.yml 方式でも可。その場合は生成手順をREADMEに明記）
- UIは日本語。コード内の識別子とコメントは英語

## 機能仕様

### 1. スキャン
- 対応コード: QR / EAN-13 / EAN-8 / UPC-E / Code 39 / Code 93 / Code 128 / Interleaved 2 of 5 / ITF-14 / PDF417 / Aztec / DataMatrix（いずれもAVFoundationが標準で検出できる種別）
- 起動したら即スキャン可能（トップ画面やチュートリアルを挟まない）
- ライト（トーチ）ON/OFF
- 写真ライブラリの画像からの読み取り（PhotosPickerで画像を選び、Visionで検出する。画像内に複数のコードがある場合は一覧から選ばせる。検出できなかった場合は「コードが見つかりませんでした」と表示する）
- 連続スキャンモード（同じコードを二重に記録しない）
- 読み取り時に触覚フィードバック（設定でOFF可）

### 2. 結果表示
- 種類を判定して表示: URL / Wi-Fi接続情報 / 連絡先（vCard）/ メール / 電話 / SMS / 地図座標 / プレーンテキスト
- 種類に応じたアクション: URLを開く、Wi-Fiに接続（NEHotspotConfigurationを使う。Hotspot Configuration のCapabilityを有効化すること）、連絡先に追加（システムの新規連絡先画面を開き、保存はユーザーが行う）、コピー、共有
- URLは開く前に全文を表示する（ドメインだけ見せて誤タップさせるような真似はしない）

### 3. 履歴
- スキャン・作成の両方を自動保存（設定で自動保存OFF可）。日時・種類・内容で検索、種類でフィルタ
- お気に入り、削除（単体・全件。全件削除は確認ダイアログを出す）、CSVエクスポート（内容にカンマ・改行・引用符が含まれても壊れないよう、RFC 4180形式でクォートすること）

### 4. QR作成
- テキスト / URL / Wi-Fi / 連絡先 / カレンダーイベント からQRコード生成
- 生成したQRは画像として写真ライブラリに保存・共有可能

### 5. 設定・その他
- スキャン時の音/振動のON/OFF、履歴の自動保存ON/OFF
- プライバシーポリシーと利用規約のリンク欄（URLは後で差し替えるので定数ファイルに切り出す）
- レビュー依頼は、スキャン成功が10回を超えた後の自然なタイミングで1回だけ

### 6. 工数が逼迫した場合
- QR作成の対応種類（カレンダーイベント → 連絡先の順）→ CSVエクスポート → お気に入り の順に後回しにしてよい
- スキャン・結果表示・履歴の保存と検索は削らない

## 課金設計

- 無料版でできること： スキャン無制限、履歴は直近30件まで、QR作成はテキストとURLのみ
- 「Pro（買い切り）」¥800 の非消耗型IAP 1点（StoreKit商品ID: `seijitsu-qr-reader.pro`）で解放するもの： 履歴無制限＋全種類のQR作成＋CSVエクスポート
- 無料版の制限は、ユーザーがぶつかる前に画面上で明示する。履歴画面に件数（例： 27/30件）を常時表示し、上限が近づいたら事前に知らせる。上限到達時は古いものから削除される旨を明示し、無言でデータを消さない。Pro限定のQR作成種類は、選んだ時点で初めて分かるのではなく、一覧上で事前に分かる表示にする
- 課金画面に「これは買い切りです。毎月・毎週の支払いは発生しません」「広告は今後も入れません」と明記し、購入ボタンには価格をそのまま表示する
- iPhone / iPad はユニバーサル購入とし、1回の購入で両方で使えるようにする
- 購入の復元（リストア）ボタンを課金画面と設定画面の両方に置く
- 無料お試し・期間限定価格など誤認させる表現、隠れたサブスク、作業の途中で課金画面を挟む導線は使わない

## 権限とプライバシー

- カメラ（NSCameraUsageDescription）: 「QRコードとバーコードを読み取るためにカメラを使用します。読み取った内容が外部に送信されることはありません」
- 写真ライブラリへの追加（NSPhotoLibraryAddUsageDescription）: 「作成したQRコードの画像を写真に保存するために使用します」。画像からの読み取りは PhotosPicker を使い、写真ライブラリ全体へのアクセス許可は求めない
- 連絡先・カレンダーへのアクセス許可が必要な実装になった場合は、勝手に追加せず報告する（連絡先への追加はシステムの画面で行う想定）
- トラッキングなし（ATTダイアログを出さない）、解析SDKなし
- App Privacy（プライバシーラベル）が「データを収集しない」になる設計にすること
- プライバシーラベル等の申告内容と実装を一致させる。申告と異なるデータ収集が必要になった場合は、勝手に実装せず報告する

## 共通デフォルト（全アプリ共通）

### デザイン原則
- **Appleの Human Interface Guidelines (HIG) に必ず沿うこと。** ナビゲーション構造、タップ領域（iPhone / iPad は44×44pt以上）、Safe Area、Dynamic Type、ダークモード、SF Symbolsの使い方など、HIGの規定から外れるUIを勝手に作らない。HIGと自分の判断が衝突したらHIGを優先し、その旨を報告する [1]
- iOS標準の見た目と操作感を基本とし、独自UIは必要最小限にする
- **レイアウト**: サイズクラス（実際に使える幅と高さ）でレイアウトを決め、端末の種類や向きで決め打ちしない [2]
- **画面の向き**: iPhoneは縦向き（ポートレート）固定。向きを固定していても、ウィンドウサイズの変化（Mac上のiPhoneミラーリング、iOS 27以降のシーンのリサイズ）でレイアウトが崩れないようにする。iPadは全方向に対応し、ウィンドウ表示で自由にリサイズされても崩れず、最小ウィンドウでも主要機能が使えるようにする。`UIRequiresFullScreen` は使わない [2][3]
- **iPhoneの操作性**: 片手操作を想定し、主要アクション（シャッター周りの操作、ライト、画像から読み取り）は画面の下部〜中部に配置する。シート（ハーフモーダル）の開閉操作は全画面で一貫させる
- **iPadのレイアウト**: 画面幅を活かしたレイアウトにする（履歴はサイドバー＋詳細など。iPhone画面の引き伸ばしにしない）。ポインタのホバー効果と、ハードウェアキーボードの主要ショートカットに対応し、主要コマンドはiPadのメニューバーにも出す（メニューバーにしかない機能は作らない）
- **キーボード表示時**: 検索欄やQR作成の入力時、ソフトウェアキーボードで入力中の項目や確定ボタンが隠れないよう、スクロールやレイアウト回避を行う
- **起動画面**: Launch ScreenをInfo.plistで構成する（iOS 27 SDK以降は提出の必須条件）。シンプルにし、広告・ロゴアニメ・待機演出を入れない。起動したらすぐスキャンできる状態にする [4]

### アプリアイコン
- レイヤードアイコン（.icon）を **Icon Composer**（Xcode同梱のApple公式ツール）または **fresnel**（kajisho5/fresnel）で作成し、iOSの **Liquid Glass** スタイルにする [5][6][7]
- キャンバスは1024×1024px。レイヤーは角丸マスクを付けない正方形で渡し、前景はベクター（SVG / PDF）を優先する
- ハイライト・影・ぼかしなどの効果は描き込まず、システムの効果に任せる
- デフォルト／ダーク／クリア（ライト・ダーク）／ティント（ライト・ダーク）の外観をすべて用意し、それぞれで見え方を確認する
- アイコンに文字を入れない。小さいサイズでも判別できるシンプルなグリフにする [5]

### 品質・標準対応
- **ダークモード**: 色はアセットカタログまたはシステムカラーで定義し、ライト／ダーク両モードで表示を確認する
- **Dynamic Type**: システムの文字サイズ変更に対応し、最大サイズ（アクセシビリティサイズを含む）でもレイアウトが崩れない
- **アクセシビリティ**: 主要な操作要素にVoiceOverラベルを付け、読み上げ順序を画面の論理順に合わせる。テキストと背景のコントラスト比を両モードで確保する（17pt以下は4.5:1以上、18pt以上と太字は3:1以上）。隣接するコントロールの間に十分な余白をとる（目安： ベゼルありは周囲約12pt、ベゼルなしは約24pt）。カスタム書体でも最小サイズ（iPhone / iPad 11pt、Mac 10pt、Watch 12pt）を下回らない。色だけで情報を区別しない。「視差効果を減らす」がオンなら自動・反復アニメーション（スキャン枠の動きなど）を抑え、「透明度を下げる」「コントラストを上げる」がオンでも文字が読めるようにする [8]
- **ローカライズ前提**: UI文字列はハードコードせず String Catalogs（.xcstrings）で管理する（初期言語は日本語。将来の英語版に備える）
- **権限拒否・空状態**: カメラ権限が拒否された場合の代替導線（設定アプリへの誘導と、画像から読み取りへの案内）と、履歴が空の状態の画面を必ず用意する
- **プライバシーマニフェスト**: PrivacyInfo.xcprivacy を用意し、必須理由APIの申告を済ませる [9]
- **データ保持**: 履歴データはアプリのコンテナに保存してiCloudバックアップ対象とし、アップデートや機種変更でデータが消えない設計にする

### デモモックと成果物の形式
- 納品時、デモ用の画面モックを用意する: **iPhone / iPad / iPhone Duo（iPhone 2台並び）**（本アプリはMac版・Watch版がないため、Mac・Watchのモックは不要）
- モックは主要画面を実機フレームで表示した、App Store掲載素材にも転用できる品質のものにする。スクリーンショットとして使う画像は App Store Connect の必須サイズで書き出す（透過なし。サイズは提出時に最新の仕様を確認）[10]
- **iPhone Duo（2台並び）モック**: 2画面の状態（時刻・データ内容・選択状態・ライト／ダーク）を一致させ、一覧と詳細、操作前と操作後のように役割分担が分かる並びにする。端末のサイズ・角度・余白を揃える。小さく表示しても文字が読めるようにする
- **モック・スクリーンショット・サンプルデータには、明らかに架空の人名・住所・電話番号・会社名・URLを使う**（実在の人物・住所・企業を使わない。URLは example.com 等の予約済みドメインを使う）
- 確認はiPhoneで行うため、**アイコンやモックなどの視覚成果物は、SVG原版に加えてPNGのプレビューを必ず添えること**（SVGだけでは見られない）
- アイコンとモックの成果物はリポジトリ内の `deliverables/` フォルダにまとめ、READMEに一覧を載せる

- **ガイドライン4.3（スパム）対策**: 既存QRリーダーの焼き直しではなく、本アプリ固有の価値（課金まわりの透明性と、広告なし・買い切りの分かりやすさ）が伝わるよう、実装と掲載文の両方で差別化を明確にする。違いの分からない類似アプリを連続して提出しない [12]
- **商標と表現**: アプリ名・タイトル・サブタイトル・キーワード欄・説明文に、競合他社の名称・商標・製品名を使わない。根拠のない最上級表現や誇大表現（「No.1」「最速」「完全無料」など）を使わない
