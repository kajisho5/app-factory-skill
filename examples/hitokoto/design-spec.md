# ひとこと日記 デザイン設計書（実例・架空のアプリ）

> hig-design-skill の実例です。アプリ名・日記の内容はすべて架空です。モックは `mocks/`（`build.py` で再生成できます）。

## 1. 前提

- アプリの目的： 1日1行だけ日記を書き、あとから読み返せるようにする
- 主な利用者と利用場面： 寝る前や移動中に、片手で短く書きたい人
- 対応プラットフォーム： iPhone / iPhone Duo / iPad / Mac（ネイティブ）/ Apple Watch
- 確認用の画像： 2台並び（pair、一覧と詳細）と、iPhone Duo の端末の枠付き画像。どちらもこのスキルの汎用の枠なので社内の確認用。外部に出すときは Apple の公式の製品ベゼルで作り直す
- 画面の向き： iPhone は縦固定（ウィンドウサイズの変化には追従）。iPhone Duo の外側も縦だけ（1行の日記を書くアプリで、立てて置いて使う場面が少ないため。HIG は横向きの対応を勧めているが、この理由で対応しない）。iPhone Duo の内側はアプリの向きの指定に従わず表示される前提で、横・縦の両方を設計する。iPad は全方向
- 準拠： Apple の Human Interface Guidelines（2026年10月時点）。実装で HIG とぶつかったら HIG を優先し、設計者に報告する。意図して推奨から外す点（iPhone Duo の外側を縦だけ、iPad をサイドバーにする）は §1・§2 に理由つきで書く
- 判断原則： 書くまでの手数を最少にする ＞ 標準の見た目 ＞ 情報量
- 起動画面： S-01 の骨格だけ（背景とカードの形、文字なし、ライト／ダーク別）の Launch Screen。ロゴアニメ・広告なし。起動したら S-01 を表示
- 文言： すべて String Catalogs で管理する前提で設計書に書く
- 通信： 購入（S-04）だけ App Store と通信する。日記は端末内と iCloud の同期だけ
- アプリアイコン： この実例の範囲外
- 照合に使った Apple Design Resources の UI Kit の版： 未使用（寸法は `references/hig-specs.md` の値だけで描いた）

- 今日を書くはタブバーに置かず、ツールバーのボタンにする（タブバーは移動専用）
- タブとサイドバーの名前： iPhone のタブは短く「日記」、iPad・Mac のサイドバーは「すべての日記」（サイドバーは文字の幅に余裕があり、カレンダーと並べたときに一覧であることが分かりやすいため）
- 検索は全端末で用意する。iPhone・iPhone Duo は検索タブ（ボタンの形。押すとすぐキーボードが出て、終わると元のタブに戻る。プレースホルダ「日記を検索」、Return キーは「検索」。結果の行は一覧と同じ形で、押すと S-02。最近の検索は出さない）。iPad と Mac はツールバーの末尾の検索フィールド（⌘F、プレースホルダ「日記を検索」）。iPad の細いウィンドウでは末尾の検索ボタンに畳む

#### サイズクラスごとの列

| 幅 | 構成 |
|---|---|
| 横 compact（iPhone、iPhone Duo 外側、iPad の細いウィンドウ、Split View の半分） | 1列（一覧 → 詳細へ進む） |
| 横 regular で幅が足りない（iPad 縦向き、iPhone Duo 内側の縦向き） | 2列（一覧＋詳細。iPad はサイドバーを畳み、切り替えボタンで出す） |
| 横 regular で幅に余裕がある（iPad 横向き） | 3列（サイドバー＋一覧＋詳細） |

列の数はシステムの分割ビューの自動の切り替えに任せ、独自の幅の境目は決めない。Mac のウィンドウの最小は 760 × 480 pt。Mac はウィンドウが狭くなるとサイドバーを自動で畳み（目安：約1000pt 未満）、一覧と詳細の2列にする。サイドバーはツールバーの切り替えボタン（sidebar.left）と「表示」メニューで戻せる。

### 流れと確認

| 場面 | 内容 |
|---|---|
| オンボーディング | なし（起動したらすぐ S-01）|
| 権限 | 通知だけ。設定（S-06）で書き忘れ通知をオンにした時点で、説明画面（全画面のシート。スワイプで閉じられない。ボタン1つ「続ける」）→ システムのダイアログの順に出す。説明の文：「毎晩、その日のひとことがまだのときに1回だけ通知します。時刻は設定で変えられます。」（モックと同じ。通知には Info.plist の文言がないので、この画面で説明する）|
| 削除の入口 | 詳細の削除のボタン（trash。iPhone の S-02 のツールバー、iPad の詳細のツールバー、iPhone Duo の詳細の操作の列）、一覧の行を左にスワイプ、行を長押ししたメニュー（「編集」、区切り、「削除」（末尾・赤））、Mac・iPad は ⌘⌫ と「編集」メニュー |
| 破壊的な操作の確認 | 日記の削除は頻繁な操作ではなく、消えると書き直せないので、アクションシートで確認する（題名「この日記を削除しますか？」、「削除」を上に赤、「キャンセル」を下。iOS 26 では押したボタンの近くから出る）|
| 取り消し | 削除の後、一覧の下に「削除しました」と「取り消す」を出す（時間で消えるが、それだけに頼らない）。iPhone ではシェイクと、テキストの編集メニューの「取り消す」でも戻せる。iPad・Mac は ⌘Z と「編集」メニュー |
| 編集中のシートを閉じるとき | S-03 で入力があるままスワイプで閉じようとしたら、アクションシートで「変更を破棄」「編集を続ける」を出す |
| 課金画面（S-04）| 「ひとこと日記 Pro」の名前、買い切りで定期支払いがないこと、価格（現地通貨）、購入の復元、利用規約とプライバシーポリシーへのリンク。無料トライアルはない。上限の説明と購入は1枚にまとめる。下にスワイプしても閉じられる。購入が成功したら S-04 を閉じ、上限から来た場合はそのまま S-03 を開き、残り件数の表示はすぐ消す。復元が成功したら S-04 を閉じ、一覧の下に「購入を復元しました」を出す |
| 評価の依頼 | システムの依頼画面を、日記を10件保存した後に1回だけ。初回起動中には出さない |
| 状態の保存 | 再起動後も、表示中の画面・一覧のスクロール位置・S-03 の入力中の文章を戻す |
| 書き忘れた日 | カレンダー（S-05）の書いていない日を選ぶと、その日の S-03 を開く（後から書ける）|
| Watch の音声入力 | 「音声で書く」→ システムの音声入力 → 認識した文を確認画面に出し、「保存」で保存（取り消しは「キャンセル」）。今日の分がすでにあるときは、確認画面で「今日の分を置き換えます」と出し、ボタンを「置き換える」にする |

| 通知 | 通常の文 | プレビュー非表示の文 | 押したとき |

### 余白と寸法
- 画面端の余白はシステムのレイアウトマージン（モックでは iPhone 16〜20pt）
- リストはグループ表示（角丸のカード）。セルの高さは2行で約76pt、セル内の左右余白20pt
- 押せる範囲は iPhone・iPhone Duo・iPad・Watch で44×44pt以上。Mac は見た目28×28pt（最小20pt）で、押せる範囲は44ptまで広げる。ツールバーの丸ボタンの間隔は6pt以上（モックでは iPhone Duo の縦並びで10pt）
- 無料版の残り件数の文言は、行数の上限を設けずに折り返し、省略しない（最大文字サイズや英語では3行以上になる）
- S-03 の入力欄は60文字まで。上限に達すると文字数表示を「60 / 60文字」にし、それ以上は入力できない（保存は押せる）
- 数字と単位の間には半角の空白を入れない（「30件」「残り 23件」のように、数字の前の語との間だけ空ける）。
- 日付は今年の分は「10月24日（土）」、去年以前の分は「2025年10月24日（金）」。一覧は年が変わるところに年の見出しを入れる

## 4. プラットフォーム別の設計

- **iPhone**： 今日を書くは右上（ツールバー）。S-02 のツールバーは 編集 → 削除 の順（iPad・iPhone Duo も同じ順にそろえる）。一覧は本文の改行を空白に置き換えて先頭から1行で切り、末尾を「…」にする。最大文字サイズでは日付と本文を縦に積み、本文は4行まで表示して末尾を省略する（全文は S-02 で読める）。残り件数は題名の下で折り返し、行の右端の詳細へ進む印も残す。S-03 は最大文字サイズでは入力欄が縦に伸び、キャンセルと保存は入力欄の上に固定して隠れないようにする
- **iPhone Duo**：
  - 外側は右端に縦一列で、右上の丸いカメラ（Dynamic Island）から下へ ステータスバー → ツールバー（今日を書く）→ タブバー → 検索タブを並べる（位置は近似）。縦に並ぶ操作はハードウェアに合わせた位置なので、右から左の言語でも同じ側に残る。Safe Area は左右・上下で非対称として扱う
  - 場所が足りないときにあふれメニューに入る順番： 削除 → 検索。今日を書くとタブバーは最後まで残す（「…」はシステムのあふれメニュー専用で、アプリ独自の「…」は置かない）
  - 内側は横向きを主にし、左に一覧ペイン、右に詳細ペイン。詳細の文字のボタン（編集）は詳細ペインの上の横のバーに置き、記号のボタン（今日を書く・削除）とステータスバーは右端に縦に並べる。完全に開いているときは一覧を狭く、半分折ったときは一覧と詳細を同じ幅にして、中央の折り目に何もかけない（`iphone-duo-inner-landscape-S-01-folded`）
  - 内側の縦向きは iPhone と同じ横向きのバー（下にタブバー）。半分折ったときに横一文字に入る折り目に、詳細のカードとボタンがかからない配置にしてある（折り目より下は一覧の続きだけ）
  - 開くと、外側で表示していた日記を内側の詳細にそのまま表示し、入力中の文章も引き継ぐ。内側の Split View（半分の幅）では一覧だけにし、選ぶと詳細に進む
- **iPad**： 列の切り替えは上の「サイズクラスごとの列」の表。アクセシビリティサイズ（AX1〜AX5）では、横 regular でも2列まで（サイドバーは畳む）にし、一覧の行は iPhone と同じ形（日付と本文を縦に積み、本文4行まで）にする。iPhone Duo の内側も同じ。詳細の題名はツールバーの段の下に置く。ツールバーは 編集・削除・今日を書く・検索（末尾）の順。⌘N で今日を書く、⌘F で検索、⌘⌫ で削除。iPadOS 26 以降のポインタを前提にし、ツールバーのボタンはポインタが乗るとガラスのハイライト、一覧の行とサイドバーの項目は背景が淡くなる。メニューバーの項目は Mac と同じ（各タブを「表示」メニューにも入れる）
- **Mac**：
  - メニューバー： 下の表。ショートカットは標準と衝突しない
  - ツールバー： サイドバーの切り替え（sidebar.left、サイドバーの上端）、題名「すべての日記」と副題（残り件数）、編集、今日を書く、検索フィールド（末尾）。削除はメニューバーが常に見えるので「編集」メニューと ⌘⌫
  - ポインタが乗ると、一覧の行とサイドバーの項目は背景が淡くなり、ツールバーのボタンは枠が出る
  - フルスクリーンはシステムのもの（⌃⌘F、「表示」メニュー）を使う
  - シート（S-03・S-04）は左上に題名、右下に文字のボタン（「キャンセル」「保存」。保存は既定のボタンで Return で確定、esc でキャンセル）。§3 のアイコン表の xmark・checkmark は iPhone・iPhone Duo・iPad のシートだけ
  - ⌘W でウィンドウを閉じた後は、Dock のアイコンか「ウインドウ」メニューで開き直せる

  | メニュー | 項目（ショートカット）|

- **Apple Watch**： S-07 だけ。今日の本文は2行まで表示し、末尾を省略する（改行は空白に置き換える）。標準の文字サイズでは S-07 はスクロールしない1画面で、ダブルタップは「音声で書く」。スクロールが必要な大きい文字サイズではダブルタップを割り当てず、縦のスクロールは Digital Crown とタッチの両方で。「音声で書く」はマイクの記号（mic）と文字。最大文字サイズ（AX3）では題名と本文を全文折り返し（60文字まで、省略しない）、画面を縦にスクロールして「音声で書く」に届く（`watch-ultra-S-07-ax3` は先頭部分）。コンプリケーションは今日書いたかどうか（円形の小さい型は 書いた＝checkmark.circle／まだ＝circle.dashed の形の違い、長方形の型は「今日：書いた／まだ書いていません」）。常時表示では本文を隠し「書いた」とだけ表示する（`watch-ultra-S-07-aod`）。iPhone が近くにないときは端末に保存し、あとで同期する

## 5. アクセシビリティ
- VoiceOver： 一覧の各行は「10月24日、公園の銀杏が…」の順で1つの要素として読む。ボタンのラベルは画面上の文言と同じ「今日を書く」。記号だけのボタンにもラベルを付ける（検索＝「検索」、戻る＝「戻る」、削除＝「削除」、サイドバーの切り替え＝「サイドバー」（iPad・Mac）、iPhone Duo の縦並びボタンも同じ。システムのあふれメニューのラベルはシステムに任せる）。S-03 の文字数は入力欄の補足として「13文字、最大60文字」と読む。許可の説明画面のベルの絵は読まない。カレンダーの日付は「10月24日、書いた」「10月25日、まだ書いていません」と読む。S-03 の天気の記号は「晴れ」のように読み、選ばれていたら「選択中」を付ける
- 視差効果を減らす： シートの表示はクロスフェードにする
- 透明度を下げる： タブバーとサイドバーは不透明な背景にする
- 色だけで区別しない： カレンダーの書いた日は点の記号、Watch のコンプリケーションは記号の形でも区別する
