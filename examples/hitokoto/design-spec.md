# ひとこと日記 デザイン設計書（実例・架空のアプリ）

> hig-design-skill の実例です。アプリ名・日記の内容はすべて架空です。モックは `mocks/`（`build.py` で再生成できます）。

## 1. 前提

- アプリの目的： 1日1行だけ日記を書き、あとから読み返せるようにする
- 主な利用者と利用場面： 寝る前や移動中に、片手で短く書きたい人
- 対応プラットフォーム： iPhone / iPhone Duo / iPad / Mac（ネイティブ）/ Apple Watch
- 掲載用画像： 2台並び（pair、一覧と詳細）と、iPhone Duo の端末フレーム付き画像
- 画面の向き： iPhoneは縦固定（ウィンドウサイズの変化には追従）、iPadは全方向
- 判断原則： 書くまでの手数を最少にする ＞ 標準の見た目 ＞ 情報量
- 起動画面： 背景色だけの Launch Screen（ロゴアニメ・広告なし）。起動したら S-01 を表示
- 文言： すべて String Catalogs で管理する前提で設計書に書く
- アプリアイコン： この実例の範囲外

## 2. 情報設計

### 画面一覧

| ID | 画面名 | 目的 | 主な要素 | 出入り口 |
|---|---|---|---|---|
| S-01 | 日記一覧 | 過去の日記を新しい順に見る | 大きなタイトル、残り件数、日付と1行目のリスト、新規作成ボタン | 起動直後／タブ「日記」→ S-02、新規作成 → S-03 |
| S-02 | 日記の詳細 | 1日分を読む・編集に入る | 日付、本文、天気と記録時刻、編集ボタン | S-01 → 戻るで S-01／編集 → S-03（編集モード：本文が入った状態で開き、保存で S-02 に戻る） |
| S-03 | 新規作成・編集（シート） | 今日のひとことを書く・直す | 入力欄（60文字まで・入力済み文字数を表示）、キャンセル、保存（強調） | S-01 の「今日を書く」ボタン／空状態の「今日を書く」／S-02 の編集 |
| S-04 | Pro の購入（シート） | 無料版の上限（30件）を外す | 買い切りであることの説明、価格をそのまま表示した購入ボタン、購入の復元、閉じる | 上限到達時の説明 → S-04／設定 → S-04。閉じると元の画面に戻る（モックは作らない） |

### ナビゲーション（プラットフォーム別）

| | iPhone | iPhone Duo | iPad | Mac | Watch |

### アイコン（SF Symbols）
book、calendar、gearshape、square.and.pencil、magnifyingglass、chevron.backward、mic

### 余白と寸法
- 画面端の余白はシステムのレイアウトマージン（モックでは iPhone 16〜20pt）
- リストはグループ表示（角丸のカード）。セルの高さは2行で約76pt、セル内の左右余白20pt
- ボタンはすべて44×44pt以上。ツールバーの丸ボタンの間隔は6pt以上（モックでは iPhone Duo の縦並びで10pt）
- 無料版の残り件数の文言は、英語などで長くなった場合は2行まで折り返し、省略しない
- S-03 の入力欄は60文字まで。上限に達すると文字数表示を「60 / 60文字」にし、それ以上は入力できない（保存は押せる）

## 4. プラットフォーム別の設計

- **iPhone**： 「今日を書く」ボタンは右上（ツールバー）。一覧は1行目を1行で切り、末尾を「…」にする。最大文字サイズでは日付と本文を縦に積み、本文は2行まで表示。S-03 は最大文字サイズでは入力欄が縦に伸び、キャンセルと保存は入力欄の上に固定して隠れないようにする
- **iPhone Duo**： 外側は iPhone と同じ構成。「今日を書く」と検索のボタンは右側のステータスバーの下に縦に並べる（システムUIの位置は近似）。内側はサイドバー（すべての日記／カレンダー／設定）＋一覧＋詳細。開くと、外側で表示していた日記を内側の詳細にそのまま表示し、入力中の文章も引き継ぐ。内側の Split View（半分の幅）では、サイドバーを畳んで一覧＋詳細にする
- **iPad**： 横向きはサイドバー＋一覧＋詳細の3列。細いウィンドウではサイドバーを畳み、一覧＋詳細の2列、さらに狭ければ一覧のみ。⌘N で新規作成、⌘F で検索。メニューバーにも同じコマンドを出す
- **Mac**： メニューバーはアプリ名・ファイル・編集・表示・ウインドウ・ヘルプ。ショートカットは ⌘N 新規作成、⌘F 検索、⌘, 設定（標準と衝突しない）。ウィンドウの最小幅は一覧＋詳細が並ぶ幅。ツールバーの操作は新規作成の1つだけ
- **Apple Watch**： 今日のひとことと「音声で書く」だけを表示する。コンプリケーションは今日書いたかどうか（円形の小さい型はチェックの記号だけ、長方形の型は「今日：記録済み／未記録」）。常時表示では本文を隠し「記録済み」とだけ表示する。iPhoneが近くにないときは端末に保存し、あとで同期する

## 5. アクセシビリティ
- VoiceOver： 一覧の各行は「10月24日、公園の銀杏が…」の順で1つの要素として読む。ボタンのラベルは画面上の文言と同じ「今日を書く」。記号だけのボタンにもラベルを付ける（検索＝「検索」、戻る＝「戻る」、iPhone Duo の縦並びボタンも同じ）
- 視差効果を減らす： シートの表示はクロスフェードにする
- 透明度を下げる： タブバーとサイドバーは不透明な背景にする

## 7. 監査結果

見つけた抜けと修正：
- パス1（C-09）： 余白・コントロール間隔の指定がない → 「余白と寸法」を追加
- パス2： S-02 の編集ボタンの行き先が未定義 → S-03 を編集にも使うと定義 ／ 上限到達後の購入画面が未定義 → S-04 を追加
- パス3（C-03）： 最大文字サイズでの S-03（入力シート）の挙動が未定義 → 入力欄が伸び、ボタンは上に固定と追記
- パス4（C-04）： 記号だけのボタン（検索、iPhone Duo の縦並びボタン）のラベルが未定義 → アクセシビリティに追記
- パス5： サイドバーの項目名が iPhone Duo だけ「すべて」で他と不一致 → 「すべての日記」に統一しモックも修正 ／ 検索が iPhone にだけない → 全端末の検索の入り口を定義
- パス6： 残り件数の文言が翻訳で長くなった場合が未定義 → 2行まで折り返しと追記 ／ 60文字に達したときの挙動が未定義 → 追記
- パス7： 同じボタンが「新しい日記」と「今日を書く」の2つの名前で書かれていた → 「今日を書く」に統一
- パス8（W-03）： コンプリケーションの型ごとの表示が未定義 → 型ごとに追記

保留： なし

最終判定： **上限到達（8パス）。見つけた抜けはすべて修正済みだが、「新規の抜けゼロが3パス連続」は未達。** 次のループ（V-01 から観点を使い直す）で確認する。観点を毎回変えると、前の観点では見えなかった抜けが毎回見つかる、という実例として残している
