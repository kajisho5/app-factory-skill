# app-factory-skill

アプリ量産ダッシュボードのパイプライン候補（低評価の競合アプリと、その不満の内訳を分析した候補リスト）から次に作るアプリを選び、開発担当のAI（Claude等）に渡す「開発プロンプト」を作成するためのスキルです。

## 使い方

スキル対応エージェントにこのリポジトリをスキルとして読み込ませ、「パイプラインから次のアプリを選んで」「○○のプロンプトを作って」と頼むだけです。進め方の詳細は `SKILL.md` にあります。

## このスキルを使うための前提

- **候補リスト（CSV）**： 1行＝1候補で、少なくとも次の情報を持つCSVを用意してください： 対象競合アプリ名、競合の評価とレビュー数、低評価レビューの不満内訳、差別化の切り口、推定開発日数、シーズン、市場、対応プラットフォーム（列名は手元の形式に合わせて読み替えます）
- **ダッシュボード相当のもの**： 候補の状態（候補・仕様・開発中・審査中・公開・保守・撤退）を管理する場所。GitHubリポジトリである必要はなく、スプレッドシートやカンバンでも構いません。このスキルはダッシュボードを書き換えず、状態を進める案内までを行います
- **開発担当のAI／エージェント**： 生成したプロンプトを渡して実装させる相手。このスキル自体はアプリを実装しません
- 具体例： 元の環境では kajisho5/app-factory-dashboard（候補61件のCSVと事業計画を持つリポジトリ）がダッシュボードにあたります

## 構成

- `SKILL.md` — ワークフローと共通デフォルトの本体
- `templates/prompt-template.md` — プロンプトの雛形（共通デフォルト＋アプリ固有部分の差し替え枠）
- `examples/` — 作成済みプロンプトの実例2本（誠実QRリーダー / 宛名印刷 はがき・封筒）。元の環境で実際に作ったプロンプトをそのまま収録しているため、固有名詞やリポジトリ名は具体名のまま残しています

## 自分の環境に合わせる箇所

- 候補CSVの置き場所と列名
- プロンプトの保存先フォルダ（SKILL.md の手順4）
- アイコン作成手段（fresnel を使う場合はその入手先。無い場合は任意のレイヤードアイコン作成手段）
- デザイン監査に使う design-check-skill の参照先（使わない場合は SKILL.md の手順3を省略可）
- 量産ペースと、状態管理で使う状態の呼び名
- 課金の基本形（ここでは広告なし・サブスクなし・買い切りを既定にしています。自社方針に合わせて変更可）
