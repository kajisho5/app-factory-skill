# アプリ量産 共通プロンプトテンプレート

各アプリのプロンプトは、このテンプレートの「共通デフォルト」を必ず含め、後半のアプリ固有部分（コンセプト／機能仕様／課金設計）を候補ごとに差し替えて作る。

---

あなたはiOSアプリ開発のエキスパートです。以下の仕様で、新規アプリ「＜アプリ名＞」をゼロから開発してください。

## 共通デフォルト（全アプリ共通）

### デザイン原則
- **Appleの Human Interface Guidelines (HIG) に必ず沿うこと。** ナビゲーション構造、タップ領域（44pt以上）、Safe Area、Dynamic Type、ダークモード、SF Symbolsの使い方など、HIGの規定から外れるUIを勝手に作らない。HIGと自分の判断が衝突したらHIGを優先し、その旨を報告する
- iOS標準の見た目と操作感を基本とし、独自UIは必要最小限にする
- **画面の向き**: iPhoneは縦向き（ポートレート）基本で固定し、回転対応しない。iPadは回転と画面分割（Split View / Stage Manager）に対応し、ウィンドウサイズが変わってもレイアウトが崩れないようにする。例外（写真・動画系など横向きが自然なものはiPhoneでも回転対応）は候補ごとに指定する
- **iPhoneの操作性**: 片手操作を想定し、主要アクションは画面の下部〜中部に配置する。シート（ハーフモーダル）の開閉操作は全画面で一貫させる
- **iPadのレイアウト**: 画面幅を活かしたレイアウトにする（サイドバー＋詳細など。iPhone画面の引き伸ばしにしない）。ポインタのホバー効果と、ハードウェアキーボードの主要ショートカットに対応する
- **Mac対応アプリの場合**: 標準のメニューバー項目と主要操作のキーボードショートカット、ウィンドウのリサイズ追従を用意する。「Designed for iPad」で動作させる場合はその方針を明記し、Mac専用UIは作らない
- **キーボード表示時**: ソフトウェアキーボードで入力中の項目や確定ボタンが隠れないよう、スクロールやレイアウト回避を行う
- **起動画面**: Launch Screenはシンプルにし、広告・ロゴアニメ・待機演出を入れない。起動したらすぐ操作できる状態にする

### アプリアイコン
- アイコンは **kajisho5/fresnel**（Liquid Glassアイコン作成ツール、GitHub: kajisho5/fresnel）を使って作成する
- iOSの **Liquid Glass** スタイルのレイヤードアイコン（.iconバンドル）とし、必要な全サイズ・全プラットフォーム分を書き出す
- ライト／ダーク／ティントの外観バリアントも用意する
- アイコンデザインもHIGのアイコン指針に従う（文字を入れない、シンプルなグリフ、など）

### 品質・標準対応
- **ダークモード**: 色はアセットカタログで定義し、ライト／ダーク両モードで表示を確認する
- **Dynamic Type**: システムの文字サイズ変更に対応し、最大サイズでもレイアウトが崩れない
- **アクセシビリティ**: 主要な操作要素にVoiceOverラベルを付け、テキストと背景のコントラスト比を確保する
- **ローカライズ前提**: UI文字列はハードコードせず String Catalogs（.xcstrings）で管理する（初期言語は日本語）
- **権限拒否・空状態**: 権限が拒否された場合の代替導線（設定アプリへの誘導を含む）と、データが空の状態の画面を必ず用意する
- **プライバシーマニフェスト**: PrivacyInfo.xcprivacy を用意し、必須理由APIの申告を済ませる
- **データ保持**: ユーザーデータはアプリのコンテナに保存してiCloudバックアップ対象とし、アップデートや機種変更でデータが消えない設計にする

### 成果物の形式
- ユーザーは基本的にiPhoneで確認する。**アイコンやモックなどの視覚成果物は、SVG原版だけでなく、iPhoneでそのまま見られるPNG書き出し（プレビュー画像）を必ず添えること**（SVG単体ではiPhoneで確認できない）

### デモモック
- 納品時、デモ用の画面モックを用意する: **iPhone / iPad / Mac / iPhone Duo（iPhone 2台並び）**
- ただしモックはアプリの対応プラットフォーム分だけでよい。**Mac版のないアプリではMacモックは不要**
- モックは主要画面を実機フレームで表示した、App Store掲載素材にも転用できる品質のものにする
- **iPhone Duo（2台並び）モック**: 2画面の状態（時刻・データ内容・選択状態・ライト／ダーク）を一致させ、一覧と詳細、操作前と操作後のように役割分担が分かる並びにする。端末のサイズ・角度・余白を揃える

### 作業環境・リポジトリ
- 成果物はGitHubの新規パブリックリポジトリで管理し、工程ごとにコミットしてプッシュする
- リポジトリは後日プライベートに変更する前提のため、APIキー・証明書・個人情報などの秘密情報は絶対にコミットしない（キーは .gitignore 済みのローカル設定や環境変数で扱い、手順をREADMEに書く）

### 進め方
1. 最初に、プロジェクト構成と画面遷移の設計だけを提示し、私の確認を待つ
2. 以後は機能ブロックごとに実装し、各ステップでビルドが通ることを確認してから次へ進む
3. 仕様に書いていない判断が必要になったら、勝手に範囲を広げず、選択肢と推奨案を提示して確認する
